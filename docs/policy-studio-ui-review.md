# 隐私协议工作台 UI 改版说明

## 本次范围

仅修改前台界面、入口导航、公开协议阅读页样式与纯前端交互；不改变数据库结构、支付配置、已有记录及旧链接。

- 新统一入口：/tools/policy-studio/
- 上传模式：/tools/policy-studio/?mode=upload
- 模板模式：/tools/policy-studio/?mode=template
- 原上传工具 /tools/document-policy/ 自动跳转上传模式
- 原固定模板工具 /tools/privacy-policy/ 自动跳转模板模式
- 首页两张重复工具卡合并为一张“隐私协议发布工作台”
- 既有公开短链 /document-policy.html?id=... 与 /agreement.html?id=... 地址不变

## 前台体验

上传模式：本地解析 DOCX、HTML、TXT（≤5MB），预览后用户主动点击“生成正式链接”，不会因上传自动发布。

模板模式：填写公司、产品、邮箱与更新日期，使用现有 PolicyTemplate 自动预览。

两个模式共用同一发布结果区域（复制正式链接 / 打开链接）、打印 PDF、复制正文、登录态判断。移动端有底部快速操作条，桌面为双栏布局。

公开阅读页：更大的字号与行距、可调字号、打印、阅读进度、自动目录（正文存在多个语义标题时出现），针对平板和手机调整排版。渲染逻辑和历史正文读取接口没有修改。

**不显示价格**：生成工作台上完全不出现价格或会员卡片；后续付款确认页显示实际金额。

## 不接真实收款

**此 UI 分支不部署支付，不修改生产 Supabase，也不调用支付宝。**

所有 Vercel 非正式域名上，studio.js 会阻止“生成正式链接”按钮向生产 Supabase 写入新记录。预览可切换、上传、编辑、滚动和打印，不会产生真实发布。

## 与支付宝支付 PR #5 的合并注意事项

已存在独立支付分支/PR #5（当前草稿，仍未启用）。此 UI 分支和支付分支涉及入口文件不同的更改，后续应先落地/验证 UI，再将支付门禁接入 /tools/policy-studio/，确认加载 billing-gate.js / billing-gate.css 并调用 HNPayGate.ensureCanPublish，服务器仍以 billing_publish_policy RPC 校验权益。

绝不能只把付费按钮放在前台，而不部署两套服务端发布权限核验；合并前 ALIPAY_BILLING_ENABLED 必须保持 false。

## 手工验收建议

- 375px、390px、768px、1024px、1440px 下检查：无横向滚动、按钮可触达、手机顶部导航和底部操作条无重叠。
- 上传 DOCX、HTML、TXT 分别确认解析；PDF 显示不支持；大于5MB拒绝。
- 模板表单：四个必填项、邮箱格式、日期、文字预览立即更新。
- 上传后切换模板再切回上传，预览保持；复制/打印按钮可用。
- 两个旧入口跳转相应模式；首页只剩一个隐私协议工具卡。
- /document-policy.html?id=<已存在的真实id> 和 /agreement.html?id=<已存在的真实id> 保持可访问；中文长文、表格、目录及打印分页。
- 预览环境点击发布时只提示“界面预览”而不写入生产。
- 主站部署前需测试当前登录账号创建正式链接、历史链接和会员收费合并适配。
